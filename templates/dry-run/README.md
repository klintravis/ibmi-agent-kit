# ibmi-agent-kit configuration (dry-run)

The ibmi-agent-kit configuration of an invented three-partition shop, generated by the
`ibmi-kit-config` bootstrap from `discovery.json`. Every name is invented.

- Partitions: `dev` (KDEV01), `qa` (KQA01, IASP KQAIASP), `prod` (KPRD01).
- Roles: `dev` (GRPDEV), `qa` (GRPQA), `analyst` (GRPRPT, the default role).

```
README.md                      this file
policy.yaml                    the execution policy (observe mode first)
policy.tests.yaml              one allow and one deny per role x environment
commands.yaml                  Example CM promote commands, listed under command_files
profiles/.env.<partition>      profile skeletons: dev, qa, prod
verbs/smoke.yaml               the org smoke verb
.github/workflows/policy.yml   CI: policy test on every push
.mcp.json                      registers the kit server for everyone who opens Claude Code here
.claude/settings.json          client permission rules
```

## Get started

You need Node 20 or later and a built checkout of
[ibmi-agent-kit](https://github.com/klintravis/ibmi-agent-kit) (its README, Install). `<kit>` is
that checkout's folder.

1. Clone this repo and `cd` into it.
2. Run setup in this folder, in a real terminal (it hides your password):

   ```sh
   node <kit>/packages/server/dist/index.js setup
   ```

   Once the kit is published, `npx ibmi-agent-kit setup` does the same. Setup lists `dev`, `qa`
   and `prod`, asks your IBM i user and password, copies the partition's settings from
   `profiles/`, points your profile at this repo's `policy.yaml`, and tests the connection. Your
   password goes only in your own profile folder (`~/.ibmi-agent-kit`), never in this repo. If it
   prints `set it to <folder>`, set `IBMI_KIT_HOME` to that folder for your user (Windows:
   `setx IBMI_KIT_HOME "<folder>"`; macOS and Linux: an `export` line in your shell profile) and
   open a new terminal.
3. Run `claude` in this folder.
4. Approve the `ibmi-agent-kit` server when Claude Code asks: this repo's `.mcp.json` registers it.
5. Optional: run `/demo` for a guided tour. It is a skill of the kit checkout, so run it from `<kit>`,
   not from this repo.

The policy path lives in each person's profile, not in this repo or `.mcp.json`, because only the
person whose credentials a policy guards can point a profile at it.

`.mcp.json` starts the kit from `IBMI_KIT_HOME`, so it holds no path of anyone's machine.
`IBMI_5250_VIEWER=true` in it turns on the live view: opening a 5250 session starts a small page on
your own machine, and the agent returns its URL, so you can watch the screen as it works. Set it
to `"false"` to turn it off for everyone.

## Profiles

Each `profiles/.env.<partition>` holds `IBMI_HOST`, `IBMI_USER` (a placeholder), the transport and
`IBMI_PARTITION`. **A password is never written to this repo**, and no `IBMI_KIT_POLICY` either.
Don't copy the skeleton: run setup (Get started).

## Policy and tests

Every partition is in `mode: observe`. Check:

```
ibmi-agent-kit policy test policy.yaml policy.tests.yaml
```

Read the run log, then `ibmi-agent-kit policy replay` a candidate edit before changing a rule, and
move partitions to `enforce` one at a time.
